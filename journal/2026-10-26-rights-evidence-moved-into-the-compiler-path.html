Rights moved alongside live artifacts

The clearest new thread came from the rights-provenance toolchain. Its campaign work bound live Compiler artifacts to Rights provenance, connected application builds to Rights lineage, and bound Rights tests to the MNCS Language CLI. Transport evidence was updated after a Control repair, making the path between an artifact and the surrounding evidence more explicit in the repository history.

These changes place provenance beside the artifacts as they move through the toolchain. The account stays at the level of repository evidence; no Commons record or local operator bundle was available to extend it further.

Forge made the evidence path concrete, with failure still visible

Rights work recorded end-to-end Forge evidence, exercised evidence verification in a demo, and added diagnostic-schema and Compiler/Forge vertical-slice records. Forge also bound license evidence to source inputs and recorded digest checks without interpreting the underlying claims.

A bounded native VM task failure remains part of the same interval. That negative result matters because the evidence path was being exercised at the same time that its runtime boundary was still producing failures.

Language facts became reusable compiler evidence

The language repository added RFC 0049 to its ledger, added SSA function verification facts, and then reused and cached those facts and artifacts across subsequent changes. The sequence reads as a move from recomputing compiler checks toward carrying named evidence through the compilation path.

That interpretation remains deliberately bounded: the collected history shows the shape of the implementation work, not a complete runtime result or an experiment snapshot.

Control context became more inspectable

Control changes exposed Git transition evidence in journal context, forwarded environmental evidence history pages, recorded an environment claim path, and exposed the configured Rights provider to the Environment runtime.
