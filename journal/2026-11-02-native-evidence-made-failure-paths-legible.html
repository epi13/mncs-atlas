Between October 27 and November 2, 2026, MNCS development moved CheckResult and compiler output toward native JSON and bounded message streams, carried runner provenance through those streams, and kept failure fixtures visible. Control also pinned the Compiler effect target for Forge execution, giving the week a narrow operator-side companion to the test-surface work.

Failure output became structured evidence

The strongest thread came from mncs-test. Compile-failure fixtures were kept within their claimed scope, family-check failures moved to native JSON, and the test surface retained only the first CheckResult failure. Related changes recorded native CheckResult migration and compiler-inventory artifacts, making failure output easier to carry as data rather than as incidental text.

The negative results remain part of the story: the fixture and first-failure rules describe how failure is retained, not a claim that the underlying compiler or family check succeeded.

The stream carried provenance and bounded messages

A second layer routed bounded provenance hashes through MNCS and hashed runner provenance through the MNCS stream. Native CheckResult message streaming was extended, long messages were streamed, text-bound and public-JSON bounds were recorded, and unresolved messages were joined natively.

Together these changes make the result stream carry more of the context needed to interpret a check. The repository records show the shape of that transport work; they do not substitute for a live Control or experiment snapshot.

Native cursors and ordering kept output stable

The test repository also accumulated small but connected records around native projection evidence, digest continuation, key ordering, and compiler diagnostics with a native cursor. A raised public-result sort budget and native replay-schema validation show the same pressure from another angle: keep the serialized result bounded while preserving enough ordering and continuation detail to inspect it.

These are implementation traces rather than a claim about a completed end-to-end experiment.

Control pinned the compiler path for Forge

Control added a focused companion to the test work by pinning the Compiler effect target for Forge execution. That change narrows which effect target the operator surface is describing, while the rest of the interval concentrated on how the resulting checks and failures are serialized and carried.

The maintainer did not receive a Control journal-context bundle, so this entry does not infer a live operator outcome from the repository change.
