Between November 3 and November 9, 2026, MNCS work moved Forge assurance and status responsibilities toward the native kernel, made Language and Environment selection more explicit, and kept invalid manifests and uncertain terminal capture visible. The interval reads as a tightening of execution boundaries rather than a single new feature.

Forge policy moved closer to the native kernel

Forge changes moved execution assurance policy, provider status aggregation, assurance request policy, verifier match decisions, and lifecycle bundle completion into MNCS-facing paths. Later changes routed workflow status and resource policy through the native kernel and added a native provider capability policy with recorded verification evidence.

Taken together, the repository history shows policy and status work being placed nearer the execution kernel. It does not by itself establish the outcome of a live Forge run or an experiment.

Language and Environment selection became more explicit

Control routed selected Language and VM runtime inspections through Environment. In the Language family, scalar conversion was exposed, development and cold runtime builds were separated, the embedding library was built with the selected Language CLI runtime, and bounded chunked process input was added. Language Service work also kept isolated development and long workspace socket paths in view.

The Test surface then honored the explicitly selected Compiler probe during VM transport verification. These changes describe selection and transport boundaries; the scheduled maintainer did not receive a local Control context export to confirm a live session.

Failure and terminal-state evidence stayed visible

The interval retained several edges that could otherwise disappear behind a green summary. Test work repaired an invalid-manifest failure while verifying a mixed inventory with declared toolchains; Control distinguished retained, restored, and unknown terminal capture; Forge reaped owned compiler scratch after interrupted local builds.

These records are useful precisely because they preserve failure and uncertainty as states in the development trail. They are not evidence that the surrounding execution path completed successfully.

Identity and evidence boundaries tightened

Supporting changes moved Forge provider identities to native SHA-256, recorded native provider-policy verification evidence, and declared a Commons native remediation-policy provider. MNCS Models also documented residual and proportional execution and composed native micro-models with bounded DAG execution and regression evidence.

Those records make identity, policy, and model-execution boundaries more inspectable in source. The maintainer did not open a Commons interface, so the Commons repository changes are reported as owning-repository evidence rather than as public Commons activity.
